# 第一章监控：使用与上线说明

已实现完整第一章的监控，覆盖第1、2、3波和最终Boss。序章教学不混入第一章记录。

## 在后台查看

部署后进入 `/admin`，输入 `1174430282@qq.com` 登录（按要求不校验密码或邮箱验证码），点击「第一章监控」。也可访问 `/admin/chapter-monitor`。

- 默认查看最近7天，单次日期范围最多31天，按对局开局时间筛选。日期按北京时间，明细时间戳显示UTC。
- 输入小游戏用户ID，可查看该用户的登录/恢复登录记录、挑战列表、首次记录通关及每局过程。
- 点击「查看过程」，查看换武器、选卡、各波完成、击败精英/Boss、死亡来源、复活、暂停、续玩和通关时间线。
- 对局快照包含开局/当前武器、当前感悟、卡片等级、是否大成、有效游玩秒数、击杀、受伤、复活和已完成波次。
- 支持按开局版本筛选；武器对比按开局武器归类，途中换武器看时间线。
- 开发者工具、体验版及手动标记的测试设备默认排除。开发测试时勾选「包含测试对局」。

登录只检查邮箱字符串，不验证邮箱归属；任何知道该邮箱的人都可以进入后台。首次登录会创建或复用这个邮箱的账号并授予管理员权限。已有账号的密码不改动，微信登录和小游戏账号逻辑不变。

## 统计口径

1. 一次完整第一章挑战使用一个局号；暂停和本机继续存档沿用局号，重新开局生成新局号。
2. 通关比例 = 有完整开局记录且最终通关的对局 / 有完整开局记录的对局。进行中、暂停、重开等仍在分母中，因此这是观察到的通关比例，并非只统计已结束对局的胜率。
3. 首次挑战指监控上线后首次有完整开局记录的挑战；无法倒推出上线前真实的生涯首局。筛选日期不会把窗口内第二次挑战当作首局。包含测试时，测试与非测试各自判断首次挑战。
4. 老存档续玩若缺少监控局号，记录为开局缺失，不混入完整开局通关比例。
5. 死亡可复活，复活后继续同一局；超过24小时无更新的进行中/暂停记录显示「中断未结算／结果未知」，不会当成死亡。
6. 登录与开玩显示时间窗内登录用户与同窗有匹配开局记录的交集。登录记录没有版本或测试标签，此项不作为严格的版本转化漏斗。
7. 有效游玩时间按游戏处于战斗状态累计，暂停、选卡、过场和离线时间不计入。强杀进程只能看到最后成功保存/上报的进度，不能保证捕获最后一瞬间。

## 上线顺序

当前完成的是代码和隔离测试；没有执行线上部署或真实数据库迁移。

1. 后端按现有发布流程准备新版本，先对目标数据库执行新增迁移，再切换运行代码：

   ```sh
   php artisan migrate --force --path=database/migrations/2026_10_11_000001_create_game_chapter_monitor_tables.php
   ```

   迁移新增 `game_chapter_runs`、`game_chapter_events`、`game_player_logins` 三张表。登录接口也使用新表，所以必须先建表再让新代码处理请求。使用符合后端依赖要求的PHP版本。

2. 如服务器启用了路由、视图或Filament组件缓存，按原发布流程刷新。常用命令：

   ```sh
   php artisan optimize:clear
   php artisan filament:clear-cached-components
   ```

   若原项目使用了缓存优化，再按原有流程重建缓存。Filament静态资源沿用现有安装；页面异常无样式时检查既有资源发布情况。

3. 确认管理员可打开 `/admin/chapter-monitor`，再发布小游戏版本 `2026-10-11-chapter-monitor1`。上报沿用现有请求域名 `https://eat.guozeshui.top`，接口为 `/api/game-account/chapter-events`。
4. 用体验版完整试玩第一章：选卡、换武器、死后复活、暂停重进、击败Boss；后台勾选测试对局，确认同一局号包含第1至3波及通关，重开后生成新局号。
5. 正式版上线后取消测试筛选，开始观察真实用户。旧版本没有的明细不能事后补录。

## 上报与排障

- 用户身份取自登录令牌，客户端不能指定上传给另一个用户。账号切换后，旧账号缓存只会在旧账号重新登录时发送。
- 每批最多20条；失败保留本地缓存并重试；服务端以用户+局号+序号去重，乱序到达不会用旧快照覆盖较新的进度。
- 每30秒战斗更新生成进度快照，关键节点立即排队，联网后按批发送。监控请求限流与云存档分开。
- 本地最多保留1000条，超过上限先舍弃普通进度快照，必要时舍弃最旧事件；后台提示丢失计数。服务器接收最近30天事件，过期/不合法事件按条剔除，避免阻塞后续队列。因此不承诺无限期离线保存。
- 暂停续玩依赖现有本机存档；现有云存档只同步成长进度，不提供跨设备恢复同一对局。
- 开发者工具可查看 `__GAME__.chapterMonitor.queue.length` 和 `__GAME__.chapterMonitor.error`。常见错误：`network`网络失败、`http_401`登录失效、`http_404`后端尚未发布、`http_429`暂时限流、`local_storage_failed`本地缓存写入失败。
- 管理员只读API在 `/api/game-analytics/chapter-monitor/` 下提供 `summary`、`runs`、`players/{id}`、`runs/{id}`。要求管理员登录，普通小游戏登录令牌无权读取。
